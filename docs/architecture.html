Why the secrets are on the command line

Only the things that actually drive the application need them. The artifact holds {$secret:operatorId} — a reference — and the vault resolves it in memory for the instant it is typed. Grep the committed capability for teller01 and you find nothing.

Members 12345 and 23456 exist, 55555 is restricted, 99999 does not exist. Faults are armed out of band via POST /__control/fault, so a fault replay drives exactly the same URLs as a happy one.

The through-line

Everything else in the system is downstream of refusing to let these two phases blur.

a model was involved deterministic — no model

The pay-off is not cleverness, it's reviewability. A capability is a file in capabilities/ that a person reads in a pull request. It diffs. It has a version. It cannot quietly decide to do something else on Tuesday.

The rule that keeps it honest

contracts depends on nothing. surface, policy and engine depend on it and not on each other's internals. Nothing above surface knows a browser exists — which is exactly what makes a desktop adapter a plausible afternoon rather than a rewrite.

Phase one

Discovery: the model never writes a locator

The most brittle decision in the system is deliberately kept away from the least deterministic component.

The loop hands Gemini a goal and a tool surface — observe, click, type, extract, declareOutcome, escalate. What it sees on each turn is not markup and not a screenshot. It is a numbered list of controls read from the accessibility tree:

#1  textbox   ""                     in contentFrame
#2  textbox   ""                     in contentFrame
#3  button    "Sign On"              in contentFrame
#4  cell      "Member Number"        in contentFrame
#5  cell      "S-0001-12345"         in contentFrame
…
> click #3

The model says "click #3". It never says #f1_ctl05, never says table > tr:nth-child(3) > td. The recorder then decides how #3 becomes durable — synthesising a ranked descriptor — and immediately verifies that descriptor resolves back to exactly that node, narrowing with a declared nth if it doesn't.

Why the verification matters

A descriptor that was already ambiguous the moment it was recorded is a latent production failure. Catching it at record time — when the page is still on screen and a better anchor is still available — is the only cheap moment to catch it.

Three things the loop learned the hard way

  • A daily quota is not a transient error. The first backoff retried every 429, and each attempt spent another request from an already-exhausted budget. The distinction has to be made on the quota id: PerMinute is what backoff is for, PerDay is fatal.
  • Nothing detected the loop. A model that cannot make progress does not stop — it tries again. Identical actions are counted now, and a run that repeats one halts with the same "stuck" signal that routes an intervention during replay.
  • Policy refusals go back to the model as ordinary tool results, with the reason. It can then escalate instead of thrashing against a guardrail it cannot see.

Phase two

The artifact is a contract, not a recording

A step list tells you what was clicked once. A contract tells a caller what it needs, what it returns, which non-success answers are legitimate, and how to know it worked.

{
  "name": "lookupMemberSavingsBalance",     // what an agent calls
  "version": "1.0.0",
  "status": "draft",                        // a model wrote it; nobody has read it

  "inputs":   [{ "name": "memberId", "pattern": "^\\d+$", "sensitivity": "identifier" }],
  "outputs":  [{ "name": "savingsBalance", "format": "currency-usd" }],
  "outcomes": [{ "tag": "MemberNotFound", "detect": { … } }],   // ← answers, not errors

  "steps": [{
    "id": "s5",
    "intent": "Entering the member ID to search for the member.",  // ← reviewable
    "riskClass": "safe",
    "action": { "_tag": "type",
                "value": { "_tag": "param", "name": "memberId" },   // ← never a literal
                "target": { … ranked strategies … } },
    "checkpoint": { "_tag": "valueEquals", … }   // never assume the action worked
  }],

  "successCondition": { … },
  "policy":     { "allowlistRef": "corebank-readonly", "maxRiskClass": "safe" },
  "provenance": { "discoveredBy": "gemini-3.1-flash-lite",
                  "transcriptDigest": "sha256:77d9…" },  // digest, never the transcript
  "health":     { "byTenant": { … } }          // drift, per institution
}

Four non-negotiables

  • Outcomes are first class. MemberNotFound is a declared answer with a detector, returned as typed data. The brief names conflating this with failure as the most common mistake in the problem, so the split is structural — different types in the result union, not different values of a status string.
  • Values are references. {$param}, {$secret}, template. One mechanism doing two jobs: it makes the capability reusable, and it keeps regulated data and credentials out of a committed file.
  • Every step carries English intent. This is what lets someone who was not there approve it.
  • Governance is in the schema. draft → candidate → approved → deprecated. Compilation always emits draft; replay will not run a risky step from an unapproved artifact unattended.
The compiler refuses to emit

Two whole-artifact scans, both added after something got through. One rejects any artifact containing a declared secret — the first real run put an operator id into a checkpoint, a route nobody had thought about. The other rejects any artifact containing a redaction marker: a recording is evidence, evidence is redacted on the way to disk, and recompiling one once produced an anchor reading S-0001-[redacted:declared] — a capability that compiles, commits, reviews cleanly and resolves nothing.

Targeting is a ranked list, not a selector

A selector encodes the page's implementation. A role plus "the cell right of the cell reading Member Number" encodes what a person actually looks for.

Recording which rank won is what turns targeting into telemetry. A step that used to resolve at rank 0 and now resolves at rank 2 still passes — and that is precisely why it is worth surfacing. It is the earliest signal that an install's UI has moved, and it arrives long before anything breaks.

Two findings that only a real browser produced

Role is a filter, not a strategy. The first resolver treated a bare role as rank 0, so "a textbox, in the cell right of Member Number" matched every textbox on the page and reported ambiguity before the anchor was ever tried.

Chromium hides layout tables. The raw CDP tree returns LayoutTable / LayoutTableCell for presentational tables — which is every form in this class of application. Playwright's ariaSnapshot shows ARIA roles and conceals this entirely, so the earlier probe was misleading; only dumping Accessibility.getFullAXTree revealed it. Without the mapping, no relational anchor resolves anything.

Phase three

What happens after every single step

This is the piece most implementations get wrong, and the one worth reading the code for.

Recovery has two kinds, and conflating them causes real damage

Dismissing an interstitial clears an obstruction — the action already happened, and re-running a sign-on click that succeeded before the notice appeared would look for a button that no longer exists. Re-authenticating restores lost context — whatever the step did was thrown away with the session, so it must be redone.

Recovery.retriesStep makes the distinction explicit and defaults to the safer one, because re-running an action that already took effect is how a replay submits a form twice. Even then, a context-restoring recovery re-checks before re-acting: re-authentication replays the sign-on prelude, which may already have completed the interrupted step.

Six defects found by running it, not by reasoning about it

read used innerText, which is empty for an <input> — so the checkpoint designed to catch silently-rejected input caught a bug in the reader instead. Nothing waited, so checkpoints were evaluated before the navigation they were waiting for had landed. Placeholders were substituted in conditions but not in descriptors. And an extraction target was once identified by the value it was about to extract — which passes for one member and fails for everyone else.

Four things can be true

They are different types, not different values of a status field.

ReplayResult =
  | Succeeded        { outputs, stepsRun, durationMs }
  | BusinessOutcome  { outcome, data, atStep }     // an answer. never an incident.
  | Escalated        { interventionId, reason }    // outside the success/failure axis
  | Failed           { error, atStep, expected, observed, evidenceRef }

Between BusinessOutcome and Failed sits the recovery layer — invisible to the caller, fully logged. A caller should never have to know that step three needed two retries, only that it worked.

ReplayErrorMeans
InputValidationFailedCaught before a browser opened. Costs nothing, changes nothing.
TargetNotFoundEvery ranked strategy tried. This is what UI drift looks like.
AmbiguousTargetMatched several. Deliberately fatal rather than "take the first".
CheckpointFailedThe action ran; the world isn't where the artifact expected.
StepTimeoutNever settled.
PolicyDeniedThe guardrail refused. Not a bug — the system working.
SessionExpiredUnrecoverableRe-authentication didn't restore it.
UnexpectedDialogA dialog no declared recovery answers.
ApplicationErrorThe application itself broke.
SurfaceUnavailableThe browser or adapter died.

Every variant carries which step, what was expected, and what was observed — enough to debug without re-running. The CLI maps the four branches onto distinct exit codes (0 succeeded, 1 failed, 2 escalated, 3 business outcome) so a shell caller gets the same distinction the type system enforces.

One chokepoint

There is no code path where a model decides to click something and the click simply happens.

Redaction runs on the way in

Every write to evidence passes through the redactor, so there is no code path that puts regulated data on disk and then relies on a viewer to hide it. Two mechanisms, because neither suffices alone: pattern-based (SSN, Luhn-checked card numbers, emails, long digit runs) catches what we did not know was there; value-based masks exactly what the capability declared sensitive.

A mask carries the name of the field it replaced — [redacted:memberId], not [redacted]. That leaks nothing the artifact does not already publish, makes evidence readable to an auditor, and is what lets the compiler turn a masked recording back into a parameterised artifact without ever seeing the value.

Limits, stated plainly

Regex redaction has false negatives — an account-number format we have not seen gets through. The model sees unredacted page content in flight; only what is persisted is masked. Screenshots are pixels and cannot be masked after the fact, which is why they are captured sparingly. Risk classification by label is imperfect: a button labelled "OK" that wires money would be classed safe — which is why the ladder sits on top of a default-deny allowlist rather than replacing it.

Handing a live run to a person

An escalation is a call that blocks, not an error that propagates. That one decision is what makes "the run pauses, a human drives, the run resumes" literally what the code does.

Co-browsing, not a reconstruction

Two defects only a real socket surfaced

Messages were handled concurrently, so a mouse-up overtook its mouse-down — the press handler pauses to read the accessibility tree and the release handler does not. A mouse-up before its mouse-down is not a click, and it fails silently. Each connection processes strictly in sequence now: input is a sequence, not a set.

The click target was described after dispatch, by which time the navigation had destroyed the node — so every captured action had a coordinate and no name. The press is read before it is forwarded, which is also the more honest target.

Handback is two genuinely different answers. skipStep means I did it — the automation must not repeat an irreversible action. retryStep means I cleared the way — it should try again on a screen that has changed. The checkpoint still runs after a skipStep: trusting a human's word that the screen is where it should be is exactly the assumption checkpoints exist to remove.

One recording, many institutions

Hundreds of credit unions run the same vendor product. Recording per institution does not scale — and produces hundreds of artifacts that drift apart independently.

The defect that made the whole idea not work

The artifact recorded its opening step as a literal URL, so an overlay setting entryPoint changed a field nothing read. The run signed into First City and then failed on a Riverbend label — a plausible-looking wrong reason, which is exactly how a bug like that survives review.

The fix belongs in the compiler, not the overlay: a navigate URL that is the declared entry point is emitted as {{entryPoint}}, so target.entryPoint becomes load-bearing rather than decorative.

Drift telemetry is kept per institution, because the aggregate stops meaning anything once one capability serves many installs: three percent across forty tenants is either forty slightly degraded or one that has moved, and only the second is actionable. driftingSteps turns the split into a concrete proposal — these steps need an entry in this tenant's overlay — which is a reviewable pull request rather than an alert nobody knows what to do with.

The seam that makes desktop plausible

Perception is the accessibility tree, not the DOM. That is the load-bearing choice in the whole system.

Why not Gemini's computer-use model

gemini-2.5-computer-use-preview emits coordinate actions from screenshots. Excellent for discovery and wrong for this system: a coordinate carries no symbolic handle, so it cannot be re-resolved deterministically — and deterministic replay is the entire point. A general model over an accessibility-tree tool surface means what gets recorded is symbolic.

What is deliberately not built

  • Postgres persistence. packages/store has a schema and a harness and is unused. Artifacts live in git, which is where reviewable things belong; runs live in evidence/, read back by the console — so what an operator sees is exactly what an auditor would find, with no second copy to disagree.
  • Masking screenshot regions before capture. The artifact already declares which fields are sensitive, so the information exists; the work does not.
  • Promoting an operator's fix into a new artifact version. The capture is symbolic precisely so it could be — but doing it automatically would be wrong, and doing it well needs a diff UI.
One known imperfection, stated rather than hidden

Evidence run 06 reports TargetNotFound where a MemberNotFound business outcome would be better. The path is fully covered by the replay tests, and run 02 shows a stronger model declaring that outcome unprompted — the weaker model that recorded the shipped artifact declared none, so replay honestly reports that it could not find what the step needed rather than inventing an answer. The failure is accurate; the artifact is incomplete. Free-tier quota ran out before a re-record.
